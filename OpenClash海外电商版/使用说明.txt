这份说明直接针对最新调整后的 **OpenClash 完整版配置文件**，进行逐项修改对照与“傻瓜式”部署教程。教程严格保留了配置文件的原代码架构与规则顺序，方便直接照搬与排查。

 一、 用户核心修改区（填入你的账号与节点信息）

在配置文件中找到 `🌟【使用者核心配置区域】🌟` 字段，只需修改以下 3 个核心位置：

1. 修改机场订阅地址（第 25 行左右）

找到 `proxy-providers:` 下的 `url:`，把后面的默认链接替换为你的真实机场订阅链接：

proxy-providers:
  主力机场:    
    url: "https://your-sub-domain.com/link/token" # 👈 修改这里：换成你的真实机场订阅链接
    type: http
    interval: 86400

2. 修改落地住宅 IP 节点信息（第 36–122 行）

在 `proxies:` 列表中找到对应的落地节点模板，按需修改或复制。代码中提供了 **Socks5** 与 **VLESS**（包含 REALITY 及 WebSocket 协议模板）两种常见的住宅 IP 填法：

场景 A：修改 Socks5 协议住宅 IP（WiFi001 / WiFi002）

  - name: "住宅IP-Socks5-美国-WiFi001"
    type: socks5
    server: 192.0.2.1               # 👈 替换为服务商给的真实住宅 IP 或域名
    port: 10800                     # 👈 替换为 Socks5 端口
    username: "your_username"       # 👈 替换为账号（若服务商无需账号认证，直接删除整行）
    password: "your_password"       # 👈 替换为密码（若服务商无需密码认证，直接删除整行）
    udp: true                       # 保留 true，运营音视频/直播流必须开启 UDP
    dialer-proxy: "所有-手动"        # 保留不动：此字段让流量先通过机场节点做前置加速中转

场景 B：修改 VLESS 协议住宅 IP（WiFi003 / WiFi004）

针对普通 VLESS、VLESS + REALITY 以及 VLESS + WebSocket 协议，配置方式如下：

  - name: "住宅IP-VLESS-美国-WiFi003"
    type: vless
    server: 192.0.2.2                               # 👈 替换为 VLESS 节点的真实 IP 或域名
    port: 443                                       # 👈 替换为端口
    uuid: "a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d"    # 👈 替换为你的 UUID（保留英文双引号）
    udp: true
    tls: true
    servername: gateway.yourdomain.com              # 👈 替换为伪装域名 SNI（无域名填 server IP）
    
    # ---------------------------------------------------------
    # 情况 A：如果节点使用的是 VLESS + REALITY 协议，取消下方的注释（删掉 #）：
    # ---------------------------------------------------------
    # reality-opts:
    #   public-key: "YourPublicKeyHereStringLength43Chars" # 👈 填入公钥
    #   short-id: "1a2b3c4d"                               # 👈 填入 ShortId

    # ---------------------------------------------------------
    # 情况 B：如果节点使用的是 VLESS + WebSocket 协议，取消下方的注释（删掉 #）：
    # ---------------------------------------------------------
    # network: ws
    # ws-opts:
    #   path: "/your-ws-path"                              # 👈 填入 WebSocket 路径
    #   headers:
    #     Host: "gateway.yourdomain.com"                  # 👈 填入 WS 对应的 Host 域名

    dialer-proxy: "所有-手动"        # 保留不动：开启链式中转

3. 修改/新增网段分流与单机 IP 规则（第 235–248 行）

找到 `rules:` 下方的 `🌟【1-32 个特定 WiFi/VLAN 网段 绑定独立落地策略组 (顶格匹配)】🌟`。

> **⚠️ 必须遵守的匹配铁律**：
> Clash 规则遵循**自上而下优先匹配**原则。
> 1. **范围小、精准的单机 IP（如 `/32`）** 必须写在网段规则的上面；
> 2. **范围大、整个 WiFi/VLAN 网段（如 `/24`）** 写在下方；
> 3. **默认网段流量**（如路由器 LAN 默认网段 `192.168.10.0/24`）无需在顶部写规则，它会自动向下流转并命中后面的 `RULE-SET` 规则集，实现基于机场节点的常规国内外自动分流。
> 
> 

rules:

  # ================================================================
  # 🌟【1-32 个特定 WiFi/VLAN 网段 绑定独立落地策略组 (顶格匹配)】🌟
  # ================================================================
  
  # 1. 单机 IP 精准分流示例（修改或新增）：
  # 语法：- SRC-IP-CIDR,设备内网IP/32,对应的策略组名称
  - SRC-IP-CIDR,192.168.11.200/32,VLESS-美国-WiFi003   # 表示 IP 为 192.168.11.200 的指定设备，强制走 WiFi003 节点
  
  # 2. 整个 WiFi/LAN 网段分流示例（修改或新增）：
  # 语法：- SRC-IP-CIDR,网段网关IP.0/24,对应的策略组名称
  - SRC-IP-CIDR,192.168.11.0/24,Socks5-美国-WiFi001    # 表示 192.168.11.x 网段下的所有设备，强制走 WiFi001 节点
  - SRC-IP-CIDR,192.168.12.0/24,Socks5-美国-WiFi002
  - SRC-IP-CIDR,192.168.13.0/24,VLESS-美国-WiFi003
  - SRC-IP-CIDR,192.168.14.0/24,VLESS-美国-WiFi004

  # ----------------------------------------------------------------
  # 💡【手把手教你增加新网段/新节点绑定】（以增加 192.168.15.x 网段为例）
  # ----------------------------------------------------------------
  # 步骤 1：在上方的 proxies 中加好新节点（如 "住宅IP-Socks5-美国-WiFi005"）
  # 步骤 2：在 proxy-groups 中新建对应的策略组：
  #        - name: Socks5-美国-WiFi005
  #          type: select
  #          proxies:
  #            - 住宅IP-Socks5-美国-WiFi005
  # 步骤 3：在此处增加一行网段规则：
  - SRC-IP-CIDR,192.168.15.0/24,Socks5-美国-WiFi005

二、 策略组同步对应说明（改了节点名怎么同步）

如果在 `proxies:` 中修改或新增了节点名称，需要确保 `proxy-groups:`（第 180–205 行左右）中的节点与组名称完全一致：

proxy-groups:
  # 1. 集成总组（汇总展示所有独享住宅节点）
  - name: 纯静态住宅-落地组
    type: select
    proxies:
      - Socks5-美国-WiFi001
      - Socks5-美国-WiFi002
      - VLESS-美国-WiFi003
      - VLESS-美国-WiFi004

  # 2. 独立绑定的策略组（名字必须与 proxies 中的 name 一一对应，也必须与 rules 中的 SRC-IP-CIDR 完全匹配）
  - name: Socks5-美国-WiFi001
    type: select
    proxies:
      - 住宅IP-Socks5-美国-WiFi001   # 👈 必须与 proxies 里的节点 name 完全相同

  - name: VLESS-美国-WiFi003
    type: select
    proxies:
      - 住宅IP-VLESS-美国-WiFi003    # 👈 必须与 proxies 里的节点 name 完全相同

三、 OpenWrt 路由器配套划网段傻瓜式设置

为了让 `- SRC-IP-CIDR,192.168.11.0/24,...` 这类分流规则精准生效，需要在 OpenWrt 后台进行接口与无线网络的划分：

┌─────────────────────────────────────────────────────────────────┐
│                 OpenWrt 多网段隔离与 WiFi 划分三步走              │
├─────────────────────────────────────────────────────────────────┤
│ 1. 新建接口: 进入 [网络] -> [接口] -> [添加新接口]                 │
│    - 名称: TikTok_LAN                                           │
│    - 协议: 静态地址                                              │
│    - IPv4 地址: 192.168.11.1 | 子网掩码: 255.255.255.0           │
│                                                                 │
│ 2. 开启 DHCP: 在新建接口下方勾选 [开启 DHCP 服务器]                │
│    - 起始 IP: 100 | 客户数: 150 (自动分配 192.168.11.100~250 IP)  │
│                                                                 │
│ 3. 绑定 WiFi: 进入 [网络] -> [无线] -> [添加]                     │
│    - SSID: TikTok_Work_WiFi01                                   │
│    - 网络: 仅勾选刚刚新建的 TikTok_LAN                            │
└─────────────────────────────────────────────────────────────────┘

连接 `TikTok_Work_WiFi01` 的设备会获得 `192.168.11.x` 的 IP，自动命中顶部规则并被导向对应的独享住宅 IP 落地节点。

四、 排错与语法防坑注意

1. **格式防错**：修改 YAML 文件时**绝对不能使用键盘上的 `Tab` 键**，所有层级缩进必须全部使用英文空格（标准缩进为 2 个空格）。
2. **冒号与空格**：每个属性的冒号 `:` 后面**必须留有一个英文空格**（例如 `type: socks5` 正确，`type:socks5` 会引发 YAML 解析错误）。
3. **OpenClash 运行内核**：在 OpenWrt 的 OpenClash 插件设置中，请务必将运行内核切换为 **Mihomo (Meta) 内核**，链式代理 `dialer-proxy` 语法和 `.mrs` 规则集才能正确解析运行。
4. **注释符号**：取消 REALITY 或 WebSocket 选项时，请注意把整行的 `#` 连同后面的空格一并删除，并保持下方字段的层级缩进对齐。
